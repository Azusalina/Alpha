# 本机离线选择评估 v1

已实现的是**评估工具**，不是“已经拟合出用户的自我”。当前排序只按
理性分区里有至少两份证据的价值参数计算对齐分数，没有训练神经网络。
工具与真实 `rank` 共用 `model/ranking.py`；测试不能成为训练材料。

## 使用

在 `back-end-core` 中，对已经初始化／训练过的数据库执行：

```bash
python -m model.evaluation --db data/brain.sqlite3 --cases docs/evaluation.example.json
```

示例是**合成数据**，不代表用户的选择；命令只用于检查工具能否运行。
真实测试材料请放在忽略 Git 的 `data/` 中，用自己的文件替换 `--cases`。
评估结果输出到 stdout，不自动写盘；其中有来源 ID、参数及选择结果，
也属于私人资料，不要提交到 Git 或自动上传。

数据库以 SQLite `mode=ro`／`query_only` 打开，在一个事务中冻结理性状态、
历史训练来源 ID、基线 hash、effect revision。不会初始化不存在的库、
导入测试材料、更新词汇／参数或修复不一致的状态。

## 测试材料格式（仅离线实验，不是前端反馈 API）

根对象严格包含 `schema_version: 1` 和 `cases`（1–1000 项）。每项必须包含：

- `id`：唯一的事件 ID。
- `domain`：`daily`、`study` 或 `interpersonal`。
- `held_out: true`：明确声明没有将这个测试事件用于拟合／纠错学习。
- `source_ids`：该事件涉及的所有后端原文 ID；从未导入的事件填 `[]`。
  曾拟合过的任何分区材料都会被排除，包括当前 agreed／revoked，以及
  再次判为 false 的 disagreed；即使没有参数 effect，也可能已参与词汇学习。
  再次判定／撤销不抹除历史训练暴露。工具只检查 ID 重叠，
  无法检测复制、改写、漏填 ID 或人工调参带来的语义泄漏。
- `options`：2–100 个互异 `id` 的选项，每项有 `impacts`。
  impacts 的键只能是当前 `value.*` 参数，值为 `[-1,1]` 有限数，
  未填参数对评分的贡献为 0。这些影响要由人标注，尚不由自然语言推断。
- `actual_choice`：用户实际上选择的选项 ID，未知填 `null`。
- `endorsed_choice`：用户事后仍认可的选项 ID，未知填 `null`。
  不要求和实际选择相同；至少有一种标签。`null` 不等于“不认可”，
  不能使用布尔值代替选择 ID，也不能从整份输入的 `agree` 推导此标签。

目前标签是单一选项，未支持多选、并列认可、延迟认可或事件内不同理性状态。
这不是 F14 前端采集契约的批准或实现；该契约仍待共同确定。

## 怎么读结果

`full.metrics` 分别统计实际选择与事后认可；`full.by_domain` 再按三个领域
分开。分母只包括有该标签的事件：

- `labelled / answered / correct`：有标签、给出唯一首选、命中的数量。
- `coverage`：answered / labelled；`abstention_rate` 是其补数。
- `accuracy_on_answered`：correct / answered，没有回答时是 `null`，不是 0。
- `correct_over_all_labelled`：correct / labelled，将拒答保留在分母中。
- `mean_reciprocal_midrank_on_answered`：已回答事件中，正确选项排名的倒数均值。
  同分用平均名次，避免按选项 ID 排序制造个人偏好；未回答样本不进入
  这个指标，因此必须与覆盖率一起看。
- `uniform_random_top1_reference`：所有有标签事件的 `1 / 选项数` 均值。
  它是全覆盖随机选项的数学参考，不是已训练基线，也不能直接用回答子集
  的准确率与它比较来宣布“胜过随机”。

证据不足、所有选项不可区分，或最高分并列（含数值容差）时拒答。
在线 rank 仍可以返回并列排序；评估不会把其中按 ID 排第一的选项算作首选。
分数不是概率，命中率也不是人格量表得分或临床评估。

## 参数消融

`ablations` 对八个 `value.*` 参数各做一次静态删除：保留相同模型快照和
测试事件，只让该参数不参与评分及证据门槛，重新计算结果。

- `changed_predictions`：首选或拒答状态发生变化的事件数。
- `paired_comparison`：在同一批有标签的事件上，删除参数后增加／失去的
  正确回答数（拒答不算命中）。避免比较不同回答子集导致误读。
- 完整指标、各领域指标和每个事件的排序仍会返回，便于检查原因。

这是**静态特征消融**，没有重新训练，也不是参数的因果效应证明。
不会自动删改用户参数。一次小样本提高准确率可能只来自偶然、注释偏差
或覆盖率变化；还需要足够的真实事件、分组／时间留出及不反复调参的
最终测试集，才能决定参数去留。当前没有自动阈值或显著性检验。

报告带 `snapshot.fingerprint`、`cases_sha256`、`ranking_sha256`、
`evaluation_sha256`，用于确认模型状态、测试文件内容、评分与指标实现
是否变化；这不是隐私保护或数据加密。
